Release 1.4.0
=============
New application icon: an SD card with a wrench across it, drawn as an SVG. The
  executable's .ico is generated from that one file by tools/mkicon, so the
  icon is edited as text rather than as a binary
The Write, Verify and Read buttons moved up between the Image File and Device
  panels, where the arrows on them point at the field they act on, and each
  carries an icon: an arrow down into the device for write, one up out of it
  for read, a pair of scales for verify
Those icons share the application icon's colours -- amber for writing, slate
  for the parts of the window that are not an action, green for reading. Amber
  and green rather than red and green, which the commonest colour blindness
  cannot tell apart, and the two arrows are mirror images so direction carries
  the meaning without colour
The folder on the browse button is a modern outline drawing rather than the old
  bitmap
The progress bar reaches 100%. It was set from the first sector of the chunk it
  had just finished, so it stopped one chunk short and a 16 MB image finished
  at 96%
The progress bar is hidden until something is running, and the status bar says
  "Writing...", "Reading..." or "Verifying..." while it runs, instead of
  leaving "Clearing old partition tables..." up for the whole write
The status bar is shaded slightly against the window, so it reads as a part of
  the window rather than as blank space
Tooltips no longer appear clipped at both ends. Qt reuses one tooltip label and
  resizes it for the next tooltip; moving straight from a narrow tooltip to a
  wider one left the text cut off at the old width
Choosing an image selects SHA256, the checksum image publishers usually quote.
  A hash type chosen by hand is left alone
Paths are shown with backslashes, the way the rest of Windows writes them
The window is shorter, and the Image File Hash box no longer reserves a blank
  line for a checksum that has not been generated
The Verify button is labelled "Verify" rather than "Verify Only"
tools/make-test-images.sh also builds a GPT pair -- one image whose
  FirstUsableLBA is 2048, which the Windows GPT rewrite bug corrupts, and one
  at 34, which it does not -- for testing the GPT repair end to end
The wrench in the application icon is Feathericon's, under the MIT licence, and
  the scales are public domain. THIRD-PARTY-NOTICES.txt records both and ships
  with the program

Release 1.3.1
=============
Long tooltips wrap instead of running off the screen. Qt only word-wraps a
  tooltip it takes for rich text, so a long plain one became a single line
  clipped at both ends, showing neither its beginning nor its end
The Verify button describes itself in the status bar, the way Read and Write
  already did, rather than in a popup
Writing an MBR image with "Fix GPT after write" unchecked no longer warns that
  the partition table is at risk. There is no GPT to rewrite, so the message
  now says so and names the image as MBR
The post-write messages are about half as long, with the same information
After the backup GPT is relocated, the stale copy the image left mid-device is
  cleared, so no dead "EFI PART" signature is left for a later scan or clone to
  find. Only sectors that really hold it are touched, never a partition
Updated all translation files for the new and changed strings

Release 1.3.0
=============
Write and verify compressed images directly: a .img.gz or .img.xz is
  decompressed as it is written to the device, so no expanded copy is ever put
  on disk. Reading a device back still produces an uncompressed .img
The uncompressed size comes from the xz index, which is exact. gzip records it
  only modulo 4 GiB, so where it cannot be trusted the write runs until the
  stream ends and reports if the image did not fit
Format is decided by the file's magic bytes, not its name
A truncated or damaged compressed image is reported instead of being written
  out as far as it goes
A failed or cancelled write, read or verify now says so in the status bar and
  resets the progress bar, instead of leaving the last message on screen
An aborted write warns that the device holds a partial image and should be
  written again, which a decoder error on its own did not make clear
Added tools/make-test-images.sh, which builds raw, gzip and xz test images
  covering multi-member gzip, multi-stream xz, trailing padding, an image that
  is not a whole number of sectors, sizes past the 4 GiB gzip limit, and
  truncated and corrupt streams
Added tools/verify-flashed.sh, which compares a flashed device against its
  image byte for byte, whatever format it was written from

Release 1.2.0
=============
Identified the actual Windows defect behind the GPT corruption: on rescan it
  rewrites the primary GPT header's PartitionEntryLBA to FirstUsableLBA minus
  the entry array length, instead of leaving it pointing at the array. Images
  whose FirstUsableLBA is 34 are unaffected because that arithmetic returns
  the correct value by coincidence; ARM board images, which reserve space
  ahead of the first partition, are corrupted. See TESTING-GPT-BUG.md
The post-write dialog now states whether the image just written IS or IS NOT
  affected, computed from the image's own table rather than guessed
Added TESTING-GPT-BUG.md: a 48 MB reproducer and a Hyper-V VHDX harness that
  triggers the corruption on demand, without an SD card or an imaging tool
gptdump.py follows the primary header's AlternateLBA, so a backup GPT stranded
  mid-device is decoded instead of reported missing, and locates the entry
  array that a wrong PartitionEntryLBA no longer points at
Extra confirmation before writing to a device that has mounted drive letters
Removed "Read Only Allocated Partitions": it parsed only the MBR, so it did
  nothing useful on the GPT cards this tool is aimed at
Renamed the hash group to "Image File Hash" and its tooltip to match, since it
  hashes the image file and never the device
Device and hash dropdowns size to their contents; Device moved onto its own row
Updated all translation files for the new and changed strings
deploy.sh empties dist/ instead of deleting it, so an open Explorer window no
  longer breaks packaging

Release 1.1.0
=============
Fork release. Changes against 1.0.0:

Fixed the Windows GPT corruption that left written cards unbootable, and
  added the "Fix GPT after write" option; see README.md
Zero stale partition tables at both ends of the device before writing
Lock every volume on the target disk while writing, then offline and eject
  the disk before the locks are released
Removed the installer; updated to Qt 6
Added build notes, deploy scripts and a GitHub Actions workflow that
  cross-compiles for win64 from Linux
Enumerate physical disks instead of drive letters, so a device with no
  mounted volume — a card holding a Linux image, for one — still appears
Added the "Show all devices" option for internal card readers that present
  the card as a fixed, non-removable disk; the Windows system disk is never
  listed either way
Refresh the device list on a timer as well as on device-arrival broadcasts,
  since a card going into a reader that exposes no volume broadcasts nothing
Lock and dismount every volume on the disk for reads and verifies, as writes
  already did
Device list shows drive letters, size and model; the dropdown sizes itself to
  fit them
Report an error when the file for a checksum cannot be opened, rather than
  presenting the hash of nothing as valid
